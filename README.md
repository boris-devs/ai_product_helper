# AI Product Helper

Прототип сервиса: по данным о контрольно-измерительном приборе (название, производитель, характеристики, описание) создаёт черновик карточки товара для B2B-магазина: SEO-заголовок до 70 символов, SEO-описание 800–1200 символов, список характеристик, 3–5 поисковых запросов и блок для менеджера. Результат отдаётся в JSON и Markdown, все генерации сохраняются в PostgreSQL.

**Стек:** Python 3.12, uv, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, PostgreSQL 16, httpx, loguru, pytest, Docker. LLM — через [OpenRouter](https://openrouter.ai), модель задаётся в `.env`.

## Запуск через Docker

1. Создайте `.env` из шаблона:

```bash
cp .env.example .env
```

2. Впишите в `.env` ключ `OPENROUTER_API_KEY` ([openrouter.ai/keys](https://openrouter.ai/keys)) и `OPENROUTER_MODEL`, например `openai/gpt-4o-mini`. Нужна обычная instruct-модель: reasoning-модели могут вернуть пустой ответ, бесплатные `:free` часто отвечают 429.

3. Запустите:

```bash
docker compose up --build
```

Миграции применяются автоматически. Веб-форма: http://localhost:8000, Swagger: http://localhost:8000/docs.

Примеры результатов для `examples/input/*.json` сохраняются в `examples/output/`:

```bash
docker compose exec app python scripts/generate_examples.py
```

Тесты (без базы и ключа): `uv run pytest`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/cards` | сгенерировать карточку |
| `POST` | `/api/v1/cards/analyze` | проверить полноту данных без LLM |
| `GET` | `/api/v1/cards`, `/api/v1/cards/{id}` | история и карточка по id |
| `GET` | `/api/v1/cards/{id}/markdown` | карточка в Markdown |

Ошибки: `400` — битый JSON, `422` — неверный формат или мало данных, `502` — ошибка LLM, `503` — не задан ключ или модель.

## Структура проекта

```
app/
  main.py            точка входа
  api/               роуты, DI, обработчики ошибок
  services/          бизнес-логика: генерация, проверка входа, проверка фактов, валидация ответа, сборка характеристик
  repositories/      работа с БД
  models/            ORM-модели
  schemas/           Pydantic-схемы
  llm/               контракт LLMClient и клиент OpenRouter
  prompts/           промпты
  core/              настройки, исключения, логирование, справочник характеристик
  db/                подключение к БД
  web/static/        веб-форма
migrations/          Alembic
examples/            входные и выходные примеры
scripts/             генерация примеров
tests/               тесты
```

Сервисы зависят от протокола хранилища, а не от SQLAlchemy, а LLM скрыта за `LLMClient`: оба легко подменить, в тестах так и сделано.

## Как не допустить выдуманных характеристик

- Модель пишет только тексты, список характеристик собирает код из входных данных; чего нет, помечается «данных нет».
- Характеристика из описания принимается только с дословной цитатой, которую код находит в тексте.
- Числа в сгенерированных текстах сверяются с входными данными.
- Ответ, не прошедший проверку (длина, число запросов, лишние числа, битый JSON), возвращается модели на исправление; оставшиеся проблемы попадают в `warnings`.
- Промпты лежат в `app/prompts/product_card.py`: правила достоверности стоят первыми, затем требования к полям и JSON-схема.

Неполные данные: без названия генерация не запускается (`422` со списком полей); отсутствие остальных полей отражается в разделе «Требует уточнения».

## Ограничения и идеи

- Справочник рекомендуемых характеристик один на все КИП, поэтому для манометра «питание» будет «данных нет».
- Проверяются только числа; выдуманный нечисловой факт ловит лишь промпт и ручная проверка.
- Генерация синхронная, без очереди, авторизации и лимитов запросов.
- Идеи: справочники по категориям приборов, второй проход LLM для сверки утверждений, structured outputs, пакетная обработка CSV/XLSX, редактирование карточек в UI.
